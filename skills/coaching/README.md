# coaching

**One behaviour, self-assessed first, rehearsed rather than advised, and observed again.**

Most call reviews describe what happened: the manager gives an accurate, fair account, the CSM agrees with all of it, and does the same thing on the next call. Nothing was wrong with the description - it just wasn't coaching, and everyone leaves feeling like it was.

This skill runs the one-to-one so behaviour actually changes. It diagnoses whether the real problem is skill, knowledge, will, or environment - four problems that wear the same clothes and need different fixes, and coaching an environment problem tells someone a structural failure is their personal deficiency. Then it picks exactly one observable behaviour, asks for the person's own read first, and rehearses it out loud in the room instead of just explaining it.

The failure this exists to prevent: **the list of six things.** Comprehensive, fair, accurate, and impossible to act on. A list of six improvements is a list of zero.

Part of the **Lead the function** group in [customer-success-skills](../../#readme).

---

## What it actually does

| Step | What you get |
| :--- | :--- |
| Diagnose before coaching | Whether this is a skill, knowledge, will, or environment problem, and the evidence for it |
| Pick one behaviour | A single observable behaviour, not a topic, chosen for leverage rather than visibility |
| Ask for the self-assessment first | Their own read on what happened, and the gap between their read and yours if there is one |
| Give feedback on the moment | A specific moment, described neutrally, with the consequence - never a verdict on the person |
| Rehearse, don't advise | The actual sentence, said out loud in the room, before the conversation ends |
| Agree the observation | What they will do, where you'll see it, and when you'll talk about it again |
| Keep it out of the wrong meetings | A check that this stayed out of the portfolio review, the forecast call, and comp conversations |

---

## Who this is for

Managers and team leads running the function rather than a single account - anyone doing a 1:1, a call review, or preparing to give a colleague feedback on how they work. It assumes you observed something yourself; it is not built to run on a secondhand report of how a call went.

---

## What this needs

**Minimum:** something you observed - a call, a written piece, a meeting. Coaching on a report of a call is coaching on rumour.

**Better with:** the recording or the artefact itself, so the conversation is about a specific moment rather than an impression, plus previous coaching notes so you aren't restarting.

**Best with:** a pattern across several observations - one call tells you about a call, three tell you about a person.

Missing context never blocks this skill - it names what it couldn't observe rather than coaching from impression.

## Where this comes from

The skill/knowledge/will/environment split sits in the same diagnostic tradition as Robert Mager and Peter Pipe's *Analyzing Performance Problems*, which separates a genuine "can't do" deficiency from a "won't do" one before anyone reaches for training or coaching as the fix. Rehearsal over advice is standard practice in behavioural skills training more broadly: a behaviour that gets said out loud and practiced is retained in a way that a behaviour that only gets explained is not.

What this skill adds is the sequencing for a CS one-to-one specifically, and the discipline of stopping at one behaviour.

---

## What this does not do

- Does not coach a knowledge gap. Teaching is faster and coaching a knowledge gap wastes the meeting
- Does not coach a will problem as if it were a skill problem - that reads as evasive and wastes months
- Does not coach an environment problem without naming it as the manager's own problem to fix
- Does not run inside a portfolio review, a forecast call, or a compensation conversation - mixing any of those with development corrupts both
