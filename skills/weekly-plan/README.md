# weekly plan

**Part of [customer-success-skills](../../#readme), CS Pulse's open library of AI skills for the work customer success actually does.**

Shapes the week around the accounts that move rather than around the calendar that filled itself. A calendar left alone fills with other people's priorities through no one's fault: reactive work carries a deadline and proactive work doesn't, so reactive wins every collision, every week, forever.

It insists the accounts get decided before the hours do - run `book-triage` first, because which accounts deserve the time and how the hours get arranged are different questions, and answering them in the wrong order produces a beautifully organized week spent on the wrong book. From there it forces exactly three outcomes for the week, not a task list: the difference between "send the renewal proposal" (can be done Friday afternoon and achieve nothing) and "the proposal is with the buyer and a review meeting is booked" (forces the sequencing backwards) is the entire exercise. Anything needing another person gets flagged to go out Monday, since a request sent Wednesday for something needed Friday fails in a way that looks like the other person's fault. The one structural fix for proactive work losing every collision: a single two-hour block, same time every week, named for the specific thing it protects rather than called "proactive time" - which is what an empty block gets called right before it's given away. Reactive load (email, tickets, Slack) gets batched into two or three windows with a stated response expectation instead of handled continuously, since continuous handling fragments every hour into pieces too small for anything else. It cuts the calendar deliberately - any recurring call nobody can name an outcome for gets shortened, cancelled or turned into an email - and it deliberately leaves a fifth of the week unscheduled as absorption capacity, because a week planned to full capacity breaks by Tuesday. It closes with a fifteen-minute Friday review that names not just what moved but why the rest didn't, since "blocked on someone else," "underestimated," and "displaced by something reactive" are three different problems with three different fixes.

The failure this exists to prevent: **the full week where nothing moved.** Forty hours, thirty meetings, every one of them legitimate, and not one account in a different position on Friday than it was on Monday.

Part of the **Run the book** group in this library.

## Who this is for

For CSMs managing more accounts than they can give equal attention to, and being honest about the tradeoffs that forces.

## What this needs

Works with nothing but your calendar and a sense of what is urgent. Gets better with a triage list, and an honest record of where last week went.

Missing context never blocks this skill. It changes what the skill can honestly claim, and it names the checks it could not run rather than guessing around the gap.

## Install just this skill

**In the Claude app, no terminal needed.** Paste this into Claude:

```
Download the weekly-plan skill from
https://github.com/CSPulse/customer-success-skills/tree/main/skills/weekly-plan,
zip the weekly-plan folder on its own, then upload it as a skill in Claude.
```

Or do it by hand: download this repository as a ZIP (or clone it), zip this folder (`skills/weekly-plan`) on its own, then in Claude go to **Customize > Skills > Create skill > Upload a skill**. The folder name inside the ZIP has to match the `name` in `SKILL.md`.
